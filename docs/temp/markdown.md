# Увод у Markdown

**Markdown** је једноставан описни језик који се користи за форматирање текста.
За разлику од програмских језика, као што су C и C#, Markdown није намењен
писању програма и извршавању инструкција, већ описивању структуре и изгледа
текстуалног садржаја. Помоћу њега можеш да означиш наслове, пасусе, листе,
линкове, слике, табеле и делове програмског кода.

Једна од главних предности Markdown-а јесте то што се документ пише као обичан
текст, без потребе за посебним уређивачем или сложеним ознакама. Изворни текст
је лако читљив чак и када се не приказује у посебно форматираном облику, а
платформе које подржавају Markdown могу да га прикажу са одговарајућим
форматирањем.

## Markdown и HTML

Markdown је настао као једноставнија алтернатива писању HTML-а за форматирање
текстуалног садржаја. Док се у HTML-у користе тагови, тј. ознаке попут `<h1>`,
`<p>` и `<table>`, у Markdown-у се за сличне потребе користе једноставнији
симболи. На пример, наслов у HTML-у можеш да напишеш овако:

```html
<h1>Мој први документ</h1>
```

У Markdown-у исти наслов записујеш на следећи начин:

```markdown
# Мој први документ
```

Као што видиш, Markdown је једноставнији за писање и читање. Ипак, он не може у
потпуности да замени HTML, јер не подржава све могућности које HTML пружа.
Такође, Markdown **није стандардизован** као HTML. HTML има формалну
спецификацију, док је Markdown током развоја добио више различитих варијанти и
проширења. Због тога исти Markdown запис не мора увек бити приказан на потпуно
исти начин у свим програмима и платформама.

## Различите варијанте Markdown-а

Током времена настало је више варијанти Markdown-а. Оне се заснивају на сличној
основној синтакси, али се разликују по правилима и додатним могућностима.
**CommonMark** је спецификација која дефинише прецизна правила за тумачење
Markdown синтаксе. Њен циљ је да смањи разлике у приказивању истог документа у
различитим програмима. **GitHub Flavored Markdown (GFM)** је проширење
Markdown-а које користи платформа GitHub. Поред основних могућности, подржава и
додатне функције, као што су табеле, прецртан текст, аутоматско препознавање
одређених линкова и листе задатака са пољима за потврду.

Постоје и друге варијанте и проширења, као што су MultiMarkdown и Markdown
Extra, а поједини програми и платформе уводе и сопствена правила или додатне
могућности. Због тога је важно да, приликом писања техничке документације за
неки софтверски пројекат, знаш на којој платформи ће документ бити приказан и
која варијанта Markdown-а се на њој користи.

## Markdown на платформи GitHub

У оквиру предмета *Развој софтверских пројеката*, Markdown ћеш пре свега
користити за писање техничке документације софтверских пројеката на платформи
GitHub. GitHub је платформа за смештање и управљање програмским кодом, сарадњу
чланова развојног тима и праћење промена на пројекту - о томе ће учити више у
лекцијама које следе. Поред програмског кода, у репозиторијуму пројекта могу се
чувати и различити документи који објашњавају чему пројекат служи, како се
користи, како се инсталира и покреће итд.

На GitHub-у се Markdown документи често користе за опис репозиторијума,
упутства за инсталацију и покретање програма, документацију програмских
компонената, описе задатака (*Issues*) и захтева за измену кода
(*Pull Requests*).

Датотека `README.md` обично садржи основне информације о пројекту. У њој могу
да се налазе назив пројекта, његова намена, упутство за покретање, потребни
алати и начин на који други програмери могу да допринесу развоју. Екстензија
`.md` означава Markdown датотеку. Њен садржај можеш да уређујеш у обичном
текстуалном едитору, а GitHub ће је приказати као форматиран документ.

## Закључак

Markdown је једноставан и практичан језик за описивање и форматирање
текстуалног садржаја. Његова главна предност је што омогућава писање прегледних
докумената без сложене синтаксе, а документација се лако чува, прегледа и мења
заједно са програмским кодом.

У овом предмету циљ није само да научиш Markdown синтаксу, већ да је примениш у
изради техничке документације софтверских пројеката на платформи GitHub. На тај
начин научићеш да јасно документујеш пројекат, објасниш његову намену и
употребу и олакшаш сарадњу са осталим члановима развојног тима.
