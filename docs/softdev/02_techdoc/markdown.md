# Основно форматирање Markdown докумената

До сада си научио да софтверски пројекат није само програмски код и да му је
потребна и **техничка документација**. Документацију ћеш често писати у описном
језику **Markdown** - једноставном описном језику за означавање текста. Текст
пишеш као обичан текст, уз употребу неколико специјалних знакова, нпр. `#`,
`*`, `>`, `` ` `` итд.. Markdown фајлови имају екстензију `.md`, а често ћеш
креирати `README.md` фајл, који GitHub аутоматски приказује на почетној
страници репозиторијума. Поред `README.md` фајла, Markdown ћеш користити и у
другим фајловима са техничком документацијом, као и на многим другим местима на
GitHub платформи.

Поред GitHub-а, Markdown или његове варијанте користе и апликације за
комуникацију и ћаскање (WhatsApp, Viber, Slack, Teams, Discord и друге), као и
апликације за белешке и продуктивност (Notion, Obsidian, Trello, Jira и друге).

> Markdown нема једну универзално прихваћену спецификацију коју све апликације
> подржавају на исти начин. Постоје различите варијанте, као што су
> **CommonMark** и **GitHub Flavored Markdown (GFM)**, које се могу разликовати
> по подржаним могућностима. У овом предмету фокус је на Markdown-у који подржава
> платформа GitHub, као и на његовом писању у код-едитору Visual Studio Code.

## Наслови

Наслове можеш да креираш навођењем једног до шест знакова `#` испред текста
наслова. Број знакова `#` одређује ниво наслова, а самим тим и његову
хијерархијску важност.

```text
# Наслов првог нивоа
## Наслов другог нивоа
### Наслов трећег нивоа
#### Наслов четвртог нивоа
##### Наслов петог нивоа
###### Наслов шестог нивоа
```

Обрати пажњу да између једног или више знакова `#` и текста наслова треба да
постоји размак (*space*), као и да наслов треба одвојити једном празном линијом
од садржаја који следи.

Када документ има два или више наслова, GitHub аутоматски генерише навигациони
садржај (енгл. *Outline*), који се отвара преко одговарајуће иконице у заглављу
фајла и омогућава брзо прелажење на жељену секцију. Зато је важно да наслове
користиш доследно и хијерархијски.

Из угла SEO оптимизације и приступачности, добра је пракса да сваки Markdown
фајл има само један наслов првог нивоа који служи као наслов целог документа
(као `<h1>` у HTML-у), док се за све подсекције користе наслови нижих нивоа.

## Стилизовање текста

Текст можеш истаћи на неколико начина:

| Стил                     | Синтакса                    | Резултат         |
| ------------------------ | --------------------------- | ---------------- |
| Подебљано                | `**текст**` или `__текст__` | **текст**        |
| Курзив                   | `*текст*` или `_текст_`     | *текст*          |
| Прецртано                | `~~текст~~`                 | ~~текст~~        |
| Подебљано и курзив       | `***текст***`               | ***текст***      |
| Индекс (испод линије)    | `<sub>2</sub>`              | H<sub>2</sub>O   |
| Експонент (изнад линије) | `<sup>2</sup>`              | x<sup>2</sup>    |
| Подвучено                | `<ins>текст</ins>`          | <ins>текст</ins> |

За подебљавање и курзив можеш користити и различите комбинације знакова:

```text
**Ово је подебљано.**
*Ово је написано курзивом.*
**Ово је _веома_ важно.**
***Све је важно.***
```

## Пасуси и прелом реда

Нови **пасус** прави се тако што се између два реда текста остави празан ред.
Да би се у `.md` фајлу извршио **прелом реда** унутар истог пасуса, на крај
првог реда може се ставити једно од следећег:

- два размака,
- обрнута коса црта (`\`),
- HTML ознака `<br>`.

На пример, коришћењем обрнуте косе црте...

```text
Овај пример\
је у два реда.
```

...ред ће се преломити након речи `пример`.

## Цитати

Текст се цитира знаком `>` на почетку реда. GitHub га приказује као издвојен
блок текста, обично увучен у односу на остатак текста и обележен вертикалном
линијом са леве стране.

```text
> Овај текст јесте цитат.

Ово је обичан пасус текста.
```

Цитати се могу користити и за истицање важних изјава или напомена у
документацији.

## Приказ кода

**Код унутар реченице** означава се једним обрнутим наводником (енгл.
*backtick*). Текст унутар њих приказује се као код, без примене осталог
форматирања.

```text
Користи `git status` да видиш све нове или измењене датотеке.
```

**Блок кода** означава се са три обрнута наводника испред и иза кода. Ако након
отварајућих наводника наведеш назив програмског језика, примениће се и
синтаксно бојење наредби.

````text
```csharp
Console.WriteLine("Hello, World!");
```
````

За приказивање програмског кода користе се ознаке попут `csharp`, `python`,
`javascript`, итд., или скраћене верзије тих ознака попут `cs`, `py`, `js` итд.
За команде које се уносе у конзоли тј. терминалу можеш користити `bash` или
`powershell`, у зависности од окружења:

````text
```bash
git status
git add .
git commit -m "Dodat README"
```
````

Ако не желиш синтаксно бојење, можеш користити ознаку `text` или једноставно
изоставити назив језика.

## Листе

Markdown подржава неуређене и уређене листе.

**Неуређена листа** почиње знаком `-`, `*` или `+`:

```text
- Прва ставка
- Друга ставка
- Трећа ставка
```

**Уређена (нумерисана) листа** почиње бројем и тачком:

```text
1. Прва ставка
2. Друга ставка
3. Трећа ставка
```

**Угнежђена листа** добија се увлачењем ставки у односу на надређену ставку.
Потребно је да унесеш размаке испред ставке угнежђене листе све док се ознака
ставке листе не нађе тачно испод првог знака текста у ставци која се налази
изнад ње.

```text
1. Прва ставка
   - Прва угнежђена ставка
     - Друга угнежђена ставка
2. Друга ставка
```

## Листе задатака

Листа задатака прави се као обична неуређена листа, али се испред текста ставља
ознака `[ ]`. Завршен задатак означава се са `[x]`.

```text
- [x] Направити репозиторијум
- [ ] Написати README.md
- [ ] Додати .gitignore
```

На GitHub-у се овакве ставке приказују као поља за означавање. У зависности од
места на ком се листа налази и дозвола корисника, поља могу бити интерактивна.

## Линкови

**Линк** се прави тако што се текст линка стави у угласте, а адреса у обичне
заграде.

```text
Овај сајт је направљен помоћу [GitHub Pages](https://pages.github.com/).
```

Текст линка мора бити у једном реду. GitHub може аутоматски препознати исправно
написане URL адресе и претворити их у линкове, али на то не треба да рачунаш.

Свака секција са насловом има аутоматски генерисано **сидро** (енгл. *anchor*)
које омогућава директно повезивање са тим делом документа. При генерисању сидра
GitHub примењује следећа основна правила:

- слова се претварају у мала слова,
- размаци се замењују цртицама (`-`),
- већина знакова интерпункције се уклања,
- форматирање се уклања (на пример, `_курзив_` постаје `курзив`),
- ако се исто сидро већ појавило у документу, додаје се цртица и број (`-1`,
`-2` итд.).

На пример:

```text
## Примери коришћења

Више о томе прочитај у одељку [Примери коришћења](#примери-коришћења).
```

Води рачуна - ако измениш наслов и тиме и његово сидро, након тога мораш
ажурирати и линкове који на њега упућују.

**Релативни линк** је линк чија се путања одређује у односу на тренутни
фајл. Ако се `README.md` налази у корену директоријума, а `CONTRIBUTING.md` у
фолдеру `docs`, линк ће изгледати овако:

```text
[Упутство за доприносе](docs/CONTRIBUTING.md)
```

GitHub аутоматски прилагођава такве линкове. Линк који почиње са `/` рачуна се
од корена репозиторијума, а могу се користити и `./` и `../`. За упућивање на
друге фајлове у истом репозиторијуму препоручују се **релативни линкови**. Они
остају употребљиви и када се репозиторијум клонира или премести, док апсолутни
линкови који воде на конкретну адресу могу бити везани за одређени
репозиторијум.

## Слике

Слика се умета слично као линк, али се испред угластих заграда ставља узвичник.
Текст у угластим заградама је **алтернативни опис** (*alt text*). Он треба
кратко да опише садржај слике и помаже корисницима који не могу да је виде.

```text
![Снимак екрана калкулатора](slike/kalkulator.png)
```

За слике које се налазе у истом репозиторијуму користе се релативне путање. На
пример, ако се слика `kalkulator.png` налази у фолдеру `slike`, путања ће бити
`slike/kalkulator.png`.

## Табеле

Табеле можеш да креираш помоћу усправних црта `|` и цртица `-`. Први ред табеле
је увек заглавље које садржи називе колона одвојене усправним цртама. Други ред
раздваја заглавље од осталих редова са подацима и треба да садржи најмање три
цртице у свакој колони. Пре табеле мораш да оставиш један празан ред како би
она била исправно приказана. На пример, овако креирана табела...

``` markdown

| Бр. | Име   | Презиме   |
| --- | ----- | --------- |
| 1   | Петар | Петровић  |
| 2   | Јован | Јовановић |
| 3   | Мира  | Мирић     |
```

...биће приказана овако:

| Бр. | Име   | Презиме   |
| --- | ----- | --------- |
| 1   | Петар | Петровић  |
| 2   | Јован | Јовановић |
| 3   | Мира  | Мирић     |

Ћелије могу да се разликују по ширини и **не мораш** их савршено поравнати
унутар колона - поравнате ћелије естетски лепше изгледају у Markdown документу,
али се рендерују (приказују) исто. Тако ће ова табела...

``` markdown

| Бр. | Име | Презиме |
| --- | --- | --- |
| 1 | Петар | Петровић |
| 2 | Јован | Јовановић |
| 3 | Мира | Мирић |
```

...бити приказана исто као и претходна:

| Бр. | Име | Презиме |
| --- | --- | --- |
| 1 | Петар | Петровић |
| 2 | Јован | Јовановић |
| 3 | Мира | Мирић |

Табела ће се исправно приказати чак иако се изоставе почетне и крајње усправне
црте у редовима испод заглавља...

``` markdown

| Бр. | Име | Презиме |
--- | --- | ---
1 | Петар | Петровић
2 | Јован | Јовановић
3 | Мира | Мирић
```

...што изворни код табеле чини још непрегледнијим.

У табели није неопходно да свака ћелија садржи податак. Ако неки податак
недостаје, одговарајућу ћелију можеш оставити празну. У следећем примеру...

``` markdown

| Име   | Презиме   | Оцена |
| ----- | --------- | ----- |
|       | Петровић  | 5     |
| Јован | Јовановић |       |
| Мира  |           | 4     |
```

...табела ће бити приказана овако:

| Име   | Презиме   | Оцена |
| ----- | --------- | ----- |
|       | Петровић  | 5     |
| Јован | Јовановић |       |
| Мира  |           | 4     |

Као што видиш, ћелије у којима нема података остају празне, али се табела и
даље исправно приказује.

Није неопходно ни да сваки ред садржи исти број елемената као заглавље. Ако ред
садржи мање елемената од броја колона, преостале ћелије ће бити празне. Следећа
табела...

``` markdown

| Име   | Презиме   | Оцена |
| ----- | --------- | ----- |
| Петар | Петровић  | 5     |
| Јован | Јовановић |
| Мира  | Мирић     | 4     |
```

...ће бити приказана овако:

| Име   | Презиме   | Оцена |
| ----- | --------- | ----- |
| Петар | Петровић  | 5     |
| Јован | Јовановић |       |
| Мира  | Мирић     | 4     |

У другом реду изворног кода недостаје податак за колону `Оцена`, па је
одговарајућа ћелија празна. Ипак, ради прегледности и лакшег одржавања кода,
препоручује се да у сваком реду наведеш све колоне, чак и када неке ћелије
немају податке.

Унутар ћелија, осим стандардног неформатираног текста, можеш слободно користити
линкове, преформатирани текст, стилизован текст и др. У следећем примеру...

``` markdown

| Бр.  | Име       | Презиме     | Сајт                          |
| ---- | --------- | ----------- | ----------------------------- |
| `1`  | **Петар** | *Петровић*  | [pera.com](https://pera.com/) |
| `2`  | **Јован** | *Јовановић* | [jova.com](https://jova.com/) |
| `3`  | **Мира**  | *Мирић*     | [mira.com](https://mira.com/) |
```

...у првој колони подаци су приказани као преформатирани текст, у другој као
задебљан текст, у трећој као укошен текст, а у четвртој као линкови:

| Бр.  | Име       | Презиме     | Сајт                          |
| ---- | --------- | ----------- | ----------------------------- |
| `1`  | **Петар** | *Петровић*  | [pera.com](https://pera.com/) |
| `2`  | **Јован** | *Јовановић* | [jova.com](https://jova.com/) |
| `3`  | **Мира**  | *Мирић*     | [mira.com](https://mira.com/) |

Такође, текст можеш поравнати улево, удесно или по средини колоне тако што ћеш
поставити двотачке `:` са леве, десне или са обе стране цртица у другом реду.
У следећем примеру:

``` markdown

| Бр. | Име   | Презиме     |
| :-- | :---: | ----------: |
| 1   | Петар | Петровић    |
| 2   | Јован | Јовановић   |
| 3   | Мира  | Мирић       |
```

...колона `Бр.` поравната је улево, колона `Име` по средини, а колона `Презиме`
удесно:

| Бр. | Име   | Презиме     |
| :-- | :---: | ----------: |
| 1   | Петар | Петровић    |
| 2   | Јован | Јовановић   |
| 3   | Мира  | Мирић       |

Да би приказао усправну црту `|` унутар ћелије, потребно је да ставиш обрнуту
косу црту `\` испред ње. У следећој табели...

``` markdown

| Усправна црта | Карактер |
| ------------- | -------- |
| Исправно      | \|       |
| Погрешно      | |        |
```

...усправна црта у првом реду приказаће се исправно, док у другом неће. Пошто
усправна црта није означена као обичан текст, парсер ће је протумачити као
раздвајач ћелија. На тај начин настаје додатна ћелија која не одговара заглављу
табеле, па ће њен садржај бити занемарен:

| Усправна црта | Карактер |
| ------------- | -------- |
| Исправно      | \|       |
| Погрешно      |          |

Функционалност рада са табелама у Markdown документима на GitHub-у је свакако
изузетно корисна, али ограничена у односу на стандардне текст едиторе као што
је Microsoft Word. Стандардном Markdown синтаксом није подржано спајање ћелија
по редовима или колонама, нити произвољно подешавање ширине сваке колоне. За
сложене табеле понекад ћеш морати ипак да користиш HTML унутар Markdown
документа јер то GitHub платформа дозвољава.

## Фусноте

Фусноте омогућавају да додаш додатно објашњење или референцу без прекидања
главног текста. У тексту се на месту фусноте пише ознака у облику `[^1]`, а
објашњење се наводи на другом месту у документу.

```text
Ово је постављена једна фуснота[^1].

Овде је још једна фуснота[^2].

[^1]: Ово је текст прве фусноте.
[^2]: Ово је текст друге фусноте.
```

Текст фуснота се увек приказује на дну документа, без обзира где си га написао
у документу, а клик на њену ознаку омогућава прелазак на место на ком је
објашњена.

## Упозорења (Alerts)

Упозорења (енгл. *Alerts*) су посебно форматирани блокови текста којима се
истичу важне информације. GitHub их подржава као проширење Markdown
синтаксе.

Постоји пет врста упозорења:

| Тип         | Намена                                  |
| ----------- | --------------------------------------- |
| `NOTE`      | Додатна корисна информација             |
| `TIP`       | Савет или препорука                     |
| `IMPORTANT` | Посебно важна информација               |
| `WARNING`   | Упозорење на проблем или опасност       |
| `CAUTION`   | Упозорење на могуће негативне последице |

Пример:

```text
> [!NOTE]
> Корисна информација коју треба знати.

> [!WARNING]
> Ова операција може довести до губитка података.
```

Упозорења користи штедљиво – само када је потребно да истакнеш неку
информацију. Немој их постављати једно за другим нити их угнежђивати у друге
елементе.

## Хоризонтална линија

Хоризонтална линија користи се за визуелно раздвајање већих целина у документу.
Прави се помоћу три или више цртица:

```text
---
```

## Коментари и приказивање специјалних знакова

**Коментар** је део изворног текста који се не приказује у форматираном
документу. У Markdown-у се пише помоћу HTML ознака за коментаре:

```text
<!-- Овај садржај се неће приказати -->
```

Ако желиш да се специјални знак прикаже као обичан знак, испред њега треба да
ставиш обрнуту косу црту `\`, слично као у језику C. Овај поступак назива се
*escape* или занемаривање посебног значења знака.

```text
Преименуј \*нови-пројекат\* у \*стари-пројекат\*.
```
