# Основно форматирање Markdown докумената

До сада си научио да софтверски пројекат није само код и да му је потребна и
**документација**: опис шта пројекат ради, како се покреће, ко га одржава итд.
Ту документацију често ћеш писати у описном језику **Markdown** - једноставном
језику за означавање текста. Текст пишеш као обичан текст, уз неколико
специјалних знакова (`#`, `*`, `>`, `` ` ``...). Markdown фајлови имају
екстензију `.md`, а често ћеш креирати фајл `README.md`, који GitHub аутоматски
приказује на почетној страни репозиторијума.

Иначе, Markdown се на GitHub-у може користити у...

- `.md` фајловима у репозиторијуму,
- описима и коментарима у *issue*-има,
- *pull request*-овима,
- *discussions* (дискусијама).

...а поред GitHub-а користе га и апликације за комуникацију и четовањеи
(WhatsApp, Viber, Slack, Teams, Discrord и др.), апликације за белешке и
продуктивност (Notion, Obsidian, Trello, Jira и др.)

> **Напомена:** приказ `.md` синтаксе није свуда исти нити потпун јер
> Markdown није стандардизован описни језик попут HTML-а. **Фокус овог предмета
> је на приказу Markdown-а на платформи GitHub или у код едитору Visual Studio
> Code.**

## Наслови

Наслов се прави тако што се испред текста стави од један до шест знакова `#`.
Број знакова одређује ниво наслова, а самим тим и величину карактера.

``` markdown
# Наслов првог нивоа
## Наслов другог нивоа
### Наслов трећег нивоа
```

Када документ има два или више наслова, GitHub аутоматски прави **садржај**
(*Outline*) којем се приступа преко иконице у заглављу фајла. Зато је добро
наслове користити доследно и хијерархијски.

## Стилизовање текста

Текст можемо истаћи на неколико начина:

| Стил | Синтакса | Пример | Резултат |
| --- | --- | --- | --- |
| Подебљано | `** **` или `__ __` | `**Ово је подебљано**` | **Ово је подебљано** |
| Курзив | `* *` или `_ _` | `_Ово је курзив_` | *Ово је курзив* |
| Прецртано | `~~ ~~` | `~~Погрешан текст~~` | ~~Погрешан текст~~ |
| Подебљано и угнежђени курзив | `** **` и `_ _` | `**Ово је _веома_ важно**` | **Ово је *веома* важно** |
| Све подебљано и курзив | `*** ***` | `***Све је важно***` | ***Све је важно*** |
| Индекс (испод линије) | `<sub> </sub>` | `H<sub>2</sub>O` | H\<sub>2\</sub>O |
| Експонент (изнад линије) | `<sup> </sup>` | `x<sup>2</sup>` | x\<sup>2\</sup> |
| Подвучено | `<ins> </ins>` | `<ins>подвучено</ins>` | \<ins>подвучено\</ins> |

У веб-едитору на GitHub-у могу се користити и пречице на тастатури: `Ctrl`+`B`
за подебљано и `Ctrl`+`I` за курзив (на Mac-у `Command`).

## Пасуси и прелом реда

Нови **пасус** прави се тако што се између два реда текста остави **празан
ред**.

Да би се у `.md` фајлу добио **прелом реда**, на крај првог реда може се
ставити једно од следећег:

- два размака,
- обрнута коса црта `\`,
- HTML таг `<br/>`.

```markdown
Овај пример\
Је у два реда
```

## Цитати

Текст се цитира знаком `>` на почетку реда. Цитирани текст се приказује
увучено, са вертикалном линијом са леве стране и сивим словима.

```markdown
Текст који није цитат

> Текст који јесте цитат
```

## Приказивање кода

**Код унутар реченице** означава се једним обрнутим наводницима (backtick).
Текст унутар њих се не форматира.

```markdown
Користи `git status` да видиш све нове или измењене фајлове.
```

**Блок кода** означава се са три обрнута наводника испред и иза кода. Ако након
отварајућих наводника наведеш назив програмског језика, примениће се и синтаксно
бојење наредби:

````markdown
``` csharp
Console.WriteLine("Zdravo, svete!");
```
````

Уколико није у питању програмски језик, уместо назива програмског језика
написаћеш `text`:

````markdown
``` text
git status
git add .
git commit -m "Dodat README"
```
````

> **Подсетник:** поруке комита пишемо латиницом и без дијакритика, као и до сада.

## Листе

**Неуређена листа** почиње знаком `-`, `*` или `+`:

```markdown
- Прва ставка
- Друга ставка
- Трећа ставка
```

**Уређена (нумерисана) листа** почиње бројем и тачком:

```markdown
1. Прва ставка
2. Друга ставка
3. Трећа ставка
```

**Угнежђена листа** добија се увлачењем ставке испод друге ставке. Маркер
угнежђене ставке треба да буде директно испод првог слова текста ставке
изнад ње.

```markdown
1. Прва ставка
   - Прва угнежђена ставка
     - Друга угнежђена ставка
```

## Листе задатака

Листа задатака прави се као обична листа, са `[ ]` испред текста. Завршен
задатак означава се са `[x]`.

```markdown
- [x] Направити репозиторијум
- [ ] Написати README.md
- [ ] Додати .gitignore
```

## Линкови

**Линк** се прави тако што се текст линка стави у угласте, а адреса у обичне
заграде:

```markdown
Овај сајт је направљен помоћу [GitHub Pages](https://pages.github.com/).
```

Текст линка мора бити у једном реду. GitHub такође аутоматски претвара у линк
исправну адресу написану у коментару.

### Линкови ка деловима документа

Свака секција са насловом има аутоматски генерисано **сидро** (*anchor*).
Правила за његово одређивање:

- слова постају мала,
- размаци се замењују цртицама (`-`),
- остали знаци интерпункције и размаци се уклањају,
- форматирање се уклања (`_курзив_` постаје `курзив`),
- ако се исто сидро већ појавило у документу, додаје се цртица и број (`-1`,
`-2`...).

```markdown
## Примери коришћења

Више у одељку [Примери коришћења](#primeri-koriscenja).
```

Ако се наслов измени, мења се и сидро, па треба ажурирати и линкове који на
њега упућују.

### Релативни линкови

**Релативни линк** је линк у односу на тренутни фајл. Ако се `README.md` налази
у корену директоријума, а `CONTRIBUTING.md` у фолдеру `docs`, линк ће изгледати
овако:

```markdown
[Упутство за доприносе](docs/CONTRIBUTING.md)
```

GitHub аутоматски прилагођава такве линкове. Линк који почиње са `/` рачуна се
од корена репозиторијума, а могу се користити и `./` и `../`. За упућивање на
друге фајлове у истом репозиторијуму препоручују се **релативни** линкови, јер
**апсолутни** могу престати да раде у клоновима репозиторијума.

## Слике

Слика се умета као и линк, али са узвичником испред. Текст у угластим заградама
је **алтернативни опис** (*alt text*).

```markdown
![Снимак екрана калкулатора](slike/kalkulator.png)
```

За слике из истог репозиторијума користе се релативне путање.

## 11. Помињање корисника и упућивање

- `@korisnik` – помиње особу и шаље јој обавештење (важи и за тимове: `@organizacija/tim`). Обавештење добија само онај ко има приступ репозиторијуму.
- `#12` – упућује на *issue* или *pull request* број 12. Куцањем знака `#` добија се листа предлога.
- `:EMOJI_KOD:` – емоџи, на пример `:+1:` или `:tada:`.

```markdown
@octocat :+1: Ово изгледа одлично, спремно је за спајање!
```

## 12. Напомене и упозорења

### Фусноте

```text
Ово је једноставна фуснота[^1].

[^1]: Моја референца.
```

Фуснота се увек приказује на дну документа, без обзира на то где је написана. Нису подржане у викију.

### Упозорења (*alerts*)

Упозорења су проширење цитата којим се истичу критичне информације. Постоји пет врста: `NOTE`, `TIP`, `IMPORTANT`, `WARNING` и `CAUTION`.

```markdown
> [!NOTE]
> Корисна информација коју треба знати.

> [!WARNING]
> Хитна информација која захтева пажњу.
```

Користе се штедљиво – један или два по чланку, не један за другим и не могу бити угнежђена у друге елементе.

## 13. Скривање и занемаривање форматирања

**Коментар** који се не приказује у документу пише се као HTML коментар:

```text
<!-- Овај садржај се неће приказати -->
```

Ако желимо да се специјални знак прикаже као обичан знак, испред њега ставимо обрнуту косу црту `\`:

```markdown
Преименујмо \*наш-нови-пројекат\* у \*наш-стари-пројекат\*.
```

Када гледамо `.md` фајл на GitHub-у, клик на **Code** искључује приказ форматирања и показује изворни текст.

## 14. Практичан пример: README за пројекат

Научено ћемо применити на пројекту **Kalkulator** из претходних лекција. Креирајмо у корену репозиторијума фајл `README.md` са следећим садржајем:

````markdown
# Kalkulator

Једноставан конзолни калкулатор написан као школски пројекат.

## Могућности

- сабирање и одузимање
- множење и дељење
- ~~степеновање~~ (планирано)

## Покретање

1. Клонирајте репозиторијум:

   ```
   git clone https://github.com/korisnik/kalkulator.git
   ```

2. Отворите пројекат у развојном окружењу.
3. Покрените програм.

## Задаци

- [x] Основне рачунске операције
- [ ] Обрада грешке при дељењу нулом
- [ ] Историја рачуна

## Допринос

Погледајте [упутство за доприносе](docs/CONTRIBUTING.md).

> [!NOTE]
> Пројекат се користи искључиво у образовне сврхе.
````

После уписивања садржаја направићемо комит и послати измене на GitHub:

````markdown
```
git add README.md
git commit -m "Dodat README"
git push
```
````

Потом отворимо репозиторијум у прегледачу и проверимо како GitHub приказује фајл.

## 15. Вежбе

1. У свом репозиторијуму направите `README.md` са насловом, кратким описом пројекта и листом могућности.
2. Додајте одељак *Покретање* са нумерисаном листом корака и блоком кода.
3. Додајте листу задатака са најмање три ставке, од којих је једна завршена.
4. Уметните слику (из фолдера у репозиторијуму) помоћу релативне путање и смисленог алтернативног описа.
5. Додајте линк ка одељку у истом документу, а затим и релативни линк ка другом фајлу.
6. Напишите реченицу у којој се знак `*` приказује као обичан знак.
7. Направите *issue* са листом задатака и пробајте да се обратите колеги помоћу `@`.

## 16. Питања за проверу

1. Шта је Markdown и која је екстензија фајлова у којима се пише?
2. Како се добија наслов трећег нивоа?
3. Која је разлика у прелому реда између `.md` фајла и коментара у *issue*-у?
4. Чему служе обрнути наводници, а чему три обрнута наводника?
5. По чему се разликују релативни и апсолутни линкови и зашто су релативни бољи за линковање унутар репозиторијума?
6. Зашто је важан алтернативни опис слике?
7. Како се у тексту приказује знак који иначе означава форматирање?
8. Које врсте упозорења (*alerts*) постоје и како треба да се користе?

## 17. Резиме

- Markdown је једноставан језик за означавање текста; пишемо га у `.md` фајловима и у коментарима на GitHub-у.
- Наслови се означавају знаком `#` (од једног до шест), а GitHub из њих прави садржај.
- Текст истичемо са `**`, `_` и `~~`; код означавамо обрнутим наводницима.
- Нови пасус захтева празан ред; у `.md` фајлу за прелом реда користимо два размака, `\` или `<br/>`.
- Листе могу бити неуређене, уређене, угнежђене и листе задатака.
- Линкови и слике имају сличну синтаксу (слика има `!` испред); за ресурсе у репозиторијуму користимо релативне путање.
- Знаком `\` поништавамо форматирање, а HTML коментаром скривамо садржај.
